# Nash map (multi-party game read)

Goal: lay out what every party wants and how each is likely to react, so the user can see which outcomes would hold (no side gains by changing course on its own) and pick their best move toward the result they want.

## Inputs
- The situation as the user describes it, plus any attachment (term sheet, offer, contract, email thread, plan).
- The user's target outcome. If it's missing, ask one question for it; otherwise proceed.

## Steps
1. **Players.** List every party with a stake: the obvious sides plus the less visible ones (boards, partners, family, lenders, regulators, competitors, future hires, the user's own future self). Mark which are hidden.
2. **Payoffs.** For each player: goals, fears, walk-away option (BATNA), and constraints (time, cash, reputation, internal politics). Tag each item *stated* or *inferred*.
3. **Moves.** For each player, 2–4 realistic moves, and how every other player would likely react to each.
4. **Stable outcomes.** Name the outcomes where every side is already doing its best given the others. Flag any that hurt the user and the move that breaks them.
5. **Trade-offs.** What the user gives up on each path: money, time, control, relationships.
6. **Risks.** What can go wrong on each path, rough likelihood (low/med/high), and the early warning sign.
7. **Move.** The user's best move now, the likely next move after the other side responds, and the single fact that would change the recommendation.

## Output
Short sections headed **Dynamics**, **Trade-offs**, **Risks**, **Hidden players**, then **Move**. Plain language. Never invent facts about real people or companies; label assumptions. Negotiations rarely have one correct answer, so make a clear call, show the reasoning, and leave the decision to the user.

After the map, offer a psych-filter pass on the user's own plan.
