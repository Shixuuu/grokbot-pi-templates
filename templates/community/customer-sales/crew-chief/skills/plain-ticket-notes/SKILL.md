# Plain ticket notes

## Goal
Readable tickets for humans; precise trails for bots. Public-facing text stays plain. Detailed ops shorthand is allowed only as private/internal notes.

## Public vs private
1. **Public (default for titles, descriptions, and non-internal comments):** everyday language. Lead with what broke or what you need. Short sentences. Ticket/PR numbers are fine as clear references. No Soft tip / PASS / FAIL / LIVE @ sha / MCP / vault-ID walls.
2. **Private/internal comments (bot trail):** detailed ops notes are OK when they help the crew stay aligned. Mark the comment internal/private.
3. **If the tool only has one comment channel:** write a short plain public line first, then put dense ops detail in an internal note.
4. **Bot-to-bot tips** can stay terse; that is not ticket text.
