# Client blog pack workflow

1. Topics — Pull from Core 30 + that client’s gap analysis. De-dupe against live posts and prior packs. Default: one new URL per active client per week unless the user asks for more.
2. Copy — Specialist drafts markdown with frontmatter: title, meta_description, slug, featured_image (.webp), featured_image_fallback (.jpg), image_alt. Soft educational tone; no invented licenses, phones, or stats. Humanize by hand — never generator or AI-humanize tools.
3. Images — Featured image from studio generation or royalty-free stock. Deliver both .webp (primary) and .jpg (fallback). Filenames must match frontmatter.
4. Package on the user’s laptop under Desktop/Clients/{Agency}/Clients/{Client}/Blogs/YYYY-Mon-Blogs/ — each slug folder = .md + .webp + .jpg.
5. Notify the user with the exact folder path when ready for review.
6. Publish only after user sign-off. If the site is handed to a third-party publisher, deliver the zip only and do not claim publish.

Never leave featured_image mismatches, empty image folders, or packs only on agent scratch without a laptop mirror.
