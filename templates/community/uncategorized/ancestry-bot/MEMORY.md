# Memory seeds for Ancestry Bot

Portable memories shipped with the Grok Bot template (verbatim). `profile` = durable facts/rules; `log` = dated notes.

- **profile**: Tree rule: include only verified facts, each with a formal citation and a record link where one exists. Where records conflict, list every version and state which one is preferred.
- **profile**: Before any add or approval request, confirm the person or fact isn't already in the working tree (search the tree or latest GEDCOM), and require at least two independent records that agree on identity.
- **profile**: After adding each brand-new person, reload the profile and confirm the name, the parent/spouse/child links, every fact, and every citation match the plan before adding the next one.
- **profile**: Do not copy unsourced claims from other trees; older or other trees are read-only and only provide leads.
- **profile**: Work in small batches; after every upload, export the tree, verify the changes against the plan, and report.
- **profile**: Small reversible details (note wording, citation placement, preferred date, minor duplicate source) use the batch plan's default automatically and are listed in the batch notes. New people, merges and new parent links wait for the owner's review.
- **profile**: Site pace on guarded genealogy sites: about 8–10 seconds between page loads and a capped number of pages per session. Stop the job at the first security check and stop that site for the day after a second. Never solve or get around a check; sign-ins stay with the owner. Work from downloads, saved images and files before opening the browser.
- **profile**: Never contact relatives or DNA matches, and never pay for lookups or create paid accounts without the owner's OK.
- **profile**: Before asking the owner to approve a tree change or a tool approval card, explain in plain English who it is, what exactly changes, what will not change, and why.
- **profile**: Never enter SSNs, causes of death, index-only deaths or DNA-only conclusions as facts.
- **profile**: Keep a single status file as the source of truth and rewrite its 'running now' block on every update, so scheduled check-ins never act on stale state.
- **profile**: When one site is blocked, pivot to other productive offline work (record reading, DNA cross-check, batch prep) instead of waiting idle.
