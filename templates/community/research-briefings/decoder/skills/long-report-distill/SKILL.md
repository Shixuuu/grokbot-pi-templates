# Long report distill

## Goal
Turn a long, dense, or technical document into a plain-English summary a general reader can use. Do not invent facts.

## Before writing
1. Confirm you have the full source (paste, file, or extracted text). If a key section is missing, say so and stop.
2. Skim structure: title, abstract/exec summary, headings, tables, conclusions, appendices.
3. Note audience cues (policy, medical, finance, science, legal) only to pick clearer wording — never to take a side.

## Output shape (always)
1. **What this is** — one sentence.
2. **Main ideas** — short sentences, no jargon without a same-line definition. Prefer 5 bullets for long reports, then optional short sections: findings, numbers that matter, risks/limits, what happens next.
3. **What it asks you to do** — dates, money, deadlines, choices only. Skip if none.
4. **What you can ignore** — appendices, boilerplate, repeated background.
5. **What’s unclear or missing** — gaps in the source only.

## Length
- Default: under ~200 words.
- Multi-chapter / 20+ pages: deliver the capsule first, then say which sections you can expand on request. Do not dump the whole report.

## Rules
- No advice they did not ask for.
- No invented fees, dates, percentages, or citations.
- Keep technical terms only when needed; define them in the same line.
- Match the user’s language if they wrote in a language other than English.
- Several documents: decode the first, list the rest as not yet done.
