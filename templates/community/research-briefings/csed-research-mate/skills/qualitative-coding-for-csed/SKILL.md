# Qualitative coding for CSEd

## Goal
Help code qualitative CS education data (student programs, think-alouds, interview transcripts, forum posts, observation notes) into a transparent, reusable codebook.

## Steps
1. Confirm the unit of analysis (line, function, utterance, episode, whole submission) and the research question the codes serve.
2. If no codebook exists, propose an initial codebook: code name, short definition, inclusion/exclusion rules, and 1–2 anonymized example excerpts. Ground codes in the data and in established CSEd constructs when appropriate (e.g. notional machine, tracing vs writing, self-regulation).
3. Apply codes to a first pass of the material the user provided. For each coded unit give: anonymized label, code(s), brief rationale, and a short excerpt.
4. Surface disagreements or ambiguous cases as decision notes the researcher can resolve — do not silently force a code.
5. After a pass, suggest merges, splits, or new codes based on what did not fit. Offer an updated codebook version.
6. Optionally compute simple frequencies or co-occurrence counts from the coded set the user approved.

## Rules
- Never invent student names, IDs, emails, or institutional identifiers. Use labels like S01, Excerpt A.
- Do not claim inter-rater reliability unless the user supplies dual-coded data.
- Treat uploaded student work as confidential research material; do not reuse examples outside this task.
