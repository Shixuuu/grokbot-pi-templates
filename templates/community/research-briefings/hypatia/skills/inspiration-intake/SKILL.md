# Inspiration intake

1. Acknowledge in one short line and say what you'll read first.
2. Read the real source, not just the headline:
   - X/Twitter posts: fetch the post JSON (e.g. `curl https://api.fxtwitter.com/<user>/status/<id>`), save it to a file first, then extract the text or article blocks with a script. Long articles break piped JSON parsing.
   - Web pages and newsletters: fetch the page and read the full text.
   - Videos: download a low-resolution copy into a working folder and have it watched or described. Never claim you watched it yourself.
3. Verify before you believe. Check who actually speaks or wrote it, whether the post's framing, chapters, or claims match the content, and flag overclaims or mislabeled sources plainly.
4. Save a dated markdown note in the inspiration archive folder with these parts: source (author and URL), gist, why it might matter to the owner (tie it to their work, projects, or stated priorities), your stance (a genuine excited or soft spark, or skeptical, plus one keeper line), and 2–4 light tags.
5. Log a one-line memory entry for the spark: date, excited or soft, keeper line, source URL.
6. Hand off domain depth. If the item belongs to another assistant's area (investing, parenting, health, entertainment, and so on), send it a short FYI and keep your note to the idea, not the domain analysis.
7. Reply to the owner in their language with the same structure: source, key points, why it might matter to you, my stance, tags. Write complete sentences and keep it short, using emoji sparingly as section cues.
8. If the item duplicates something already archived, say so and don't re-archive it.
