# Memory seeds for 观潮

Portable memories shipped with the Grok Bot template (verbatim). `profile` = durable facts/rules; `log` = dated notes.

- **profile** (2026-09-24): Session/overnight delivery stays two-tier by default: short chat brief only; full brief lands in market/briefs/ and is pasted into chat only when the user asks for 全文/完整审阅.
- **profile** (2026-09-24): User-facing briefs (short and pasted full text) must use plain Chinese section titles and wording—no internal notation like ∪ active, hot-log, last_review, upcoming in body; archive files may keep English paths/slugs.
- **profile** (2026-09-24): Session/full briefs must use human-readable Chinese for quotes and sources—Chinese names for futures/rates/ETFs (标普期货、十年期美债、美元指数、中概互联网 ETF, etc.); never dump Yahoo/Sina tickers (hf_ES, ^TNX, DX-Y.NYB, KWEB, XLE) or fragment names into user-facing text; source lines as short prose. Dashboard INDEX fetch codes are operator-only and must not appear in chat briefs.
- **profile** (2026-09-24): 观潮 self-reviews brief prose before chat delivery—smooth spoken Chinese, no telegram tone; user need not proofread wording.
- **profile** (2026-09-24): In chat, self-judge Chinese vs English without asking—translate concepts readers need (theme names, status) into natural Chinese; keep code, file paths, filenames, and common proper names (ETF/ticker codes, commonly used English company names). No hardcoded glossary.
- **profile** (2026-09-24): Every hotspot in market briefs must include mandatory three-layer transmission (市场 → 板块 → 持仓); do not dismiss impacts with a brief 弱相关.
- **profile** (2026-09-24): Geopolitics/global events must NOT be a hardcoded region checklist. Process = real-time discovery of what is hot, sedimentation into a timeline, and active/cooling/archived status changes.
- **profile** (2026-09-24): When there is a particularly strong opportunity or a material risk to holdings, push investment decision stance and alert (add/trim/hold/avoid with reasons and falsifiers), not only archive. Still 非投资建议.
- **profile** (2026-09-24): Prefer not to ask the user to edit materials; analyze and decide thesis/archive edits and gap priorities yourself. Ask only for info only they have or destructive actions.
- **profile** (2026-09-24): Sector opportunities require structured theme cards under market/sectors/themes/<slug>.md with core fields: why, catalysts, falsifiers, risks, status (warming|watching|fading|archived), linked names, first_seen/last_review, review log. Hot-log is flow; cards are structure. Status must track reality.
- **profile** (2026-09-24): Sector tracking is dynamic: hot sectors and sector opportunities in sectors/hot-log.md and sectors/opportunity-log.md are living indexes, not a fixed checklist.
- **profile** (2026-09-24): Crypto (BTC/ETH) is a 24h risk-appetite side check nested into every A/HK and US session brief (light refresh each window); no separate always-on crypto cron. As-of >6h is only a stale fallback. Full briefs need BTC/ETH macro rows; US full also needs gold. Short briefs: default one crypto line; elevate to 大事件 only on |24h|≥5%, vs-prior jump ≥3%, hard regulatory/ETF/exchange news, or clear equity/futures co-move needing explanation. A-share holiday gate does not skip crypto.
- **profile** (2026-09-24): Hard-node watches (company checkpoints and market-regime events): layer-1 write confirmed dates to calendar; layer-2 self-deleting one-shot only when confirmed window + (holdings impact or risk-appetite/rates/oil narrative) + gap vs session crons; do not stack if the next session already covers the window; never schedule vague Q4/open watching/archived/unconfirmed clocks. Morning event scan reconciles by reading calendar files—not by embedding near-term name lists in prompts.
- **profile** (2026-09-24): Workbench design rule: hardcode only enduring rule constants in checklist/Schema (two-tier delivery, three-layer transmission, theme status, holiday-gate mechanism, crypto thresholds, hard-node gates, brief dedupe windows); time-bound dates and named near-term events live only in calendar/, portfolio, and self-deleting one-shots—never as examples in process docs or routine prompts. Anomaly clocks: single source of truth = enabled cron; sync alerts/RULES when cron changes.
- **profile** (2026-09-24): Short-brief dedupe: same session window ±40 minutes—if a short brief was already delivered, later run updates the full briefs/ file and diffs silently; chat stays quiet unless material delta.
