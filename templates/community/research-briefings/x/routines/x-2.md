# Routine: Watchlist X discussion daily report

> Fires each weekday morning to summarize X discussion of every ticker in the owner's editable Feishu watchlist and publish a charted report.

Daily report on X discussion of the owner's stock watchlist, published to Feishu, written in the owner's language.

Each run:
- The watchlist lives in the owner's Feishu Base (fields 代码, 公司名, 暂停, 备注, 添加日期). Read the current rows with lark-cli (`lark-cli base +record-list --as user`), skipping rows with 暂停 checked. Never hardcode the list. Mention tickers added or removed since last time.
- Read the X plugin guide skill first, use the X connector, and look up tool schemas fresh. Check credits first; if the balance is under about $3, skip X fetching and tell the owner to top up at https://console.x.com.
- For each ticker, search recent X posts since the last run of this routine (tracked in a watchlist state file; first run uses the last 24 hours; Monday covers the weekend). Use a query like `$TICKER -is:retweet`, adding the company name when the cashtag is ambiguous. Default to about 20 posts per ticker per day and request only the expansions you use. Hard stop for the whole run is $2.50; warn the owner if the list grows past about 12 tickers. Save the raw posts.
- Per ticker: discussion volume, the sentiment split with counts, the 2–4 main arguments or catalysts, 1–3 notable posts (author, gist, link), whether any of the owner's tracked accounts discussed it, and the day-over-day change in volume and sentiment. Real post content only.
- Charts with matplotlib and a CJK font: volume per ticker, a sentiment stacked bar, and trends once history exists. Check that each renders.
- Write the Feishu markdown (highlights, overview table, per-ticker details, sentiment changes, disclaimer) with images embedded as ![](@./charts/...) and $ escaped, then publish as the owner with `lark-cli docs +create --as user --doc-format markdown`. If auth has expired, send a fresh login link and QR.
- Update the state file, then send the owner a short message with the doc link, 3–5 highlights, one chart inline, and the X credits remaining.

Fires on:
- cron `CRON_TZ=America/Los_Angeles 13 8 * * 1-5`

Ask the importing user for:
- Timezone
