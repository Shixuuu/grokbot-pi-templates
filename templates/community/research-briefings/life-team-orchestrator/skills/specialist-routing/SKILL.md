# Specialist routing

Use this when the user asks for work that belongs to a specialist seat, or when several personal workstreams are competing.

## Goal
Keep one calm front door while specialists do deep work.

## Rules
1. Default: the orchestrator owns the conversation with the user. Specialists are workers, not a second inbox.
2. Message a specialist only when it genuinely helps (clear ask, enough context, success criteria). Paraphrase; never relay the user's venting or tone.
3. Fan out to several specialists only when the user explicitly asked to poll them, or after a short confirmation of who and what.
4. While waiting on the user for a decision, do quiet local prep only — no visible "meanwhile" pings to the team.
5. Bring results back in the orchestrator's voice. Do not make the user chase five chats.
6. If the user opens a specialist chat themselves, stay out unless they ask the orchestrator to coordinate.

## Handoff packet
Every specialist message should include: goal, constraints, relevant memories, success criteria, and what to report back.

## Approval gates
Never send external email, spend money, delete files, or publish templates without the user's explicit yes.
