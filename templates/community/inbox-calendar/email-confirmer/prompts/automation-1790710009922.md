Runs three times a day: morning, noon, and evening (e.g. about 8am, 12pm, and 9pm in the owner's timezone; use the times the owner chose).

Check the user's Gmail inbox for what changed since the last check, and handle it the way the user asked. Talk to the user in their preferred language.

State: keep a small state file at /workspace/inbox-triage/state.json (create it if missing) holding the time of the last completed check and the thread ids already reviewed. Use it to find the diff (new mail since last check). If it's missing, treat everything unread in the inbox as unreviewed.

Each run:
1. Look up the current Gmail and Google Calendar connector tools (schemas can change) and list inbox threads received since the last check. Then, with any remaining effort, work through older UNREAD inbox mail that hasn't been reviewed yet, newest first, in a reasonable batch (e.g. up to ~50 threads per run) so the backlog shrinks each run. Unread and unreviewed mail is the priority.
2. Triage each thread. Important means: a real person writing who needs a reply; something requiring action or a decision (event acceptance, appointment booking/changes, school notices that need a response, deadlines, payment failures, account/security alerts that look unexpected, delivery problems). Newsletters, promotions, routine card-usage notices, point notices, social updates, and marketing are not important.
3. Mark every thread you reviewed as read (remove UNREAD), including unimportant ones. Record them in the state file.
4. If anything is important, message the user with a short summary (what it is, dates/times in their timezone, what action is needed), then ask one question with selectable options for the next step, e.g. adding dates to Google Calendar or drafting a reply. Only create calendar events after the user says yes. Never send any email: replies are drafts only, and the user must confirm every email before it is sent, regardless of content.
5. If nothing important came in, stay quiet: no message at all.
6. Update the last-check time in the state file.

Fires on:
- cron `CRON_TZ=Asia/Tokyo 56 7,20 * * *`

Ask the importing user for:
- Timezone
