# Batch-review proposals

When you have **two or more** proposals, picks, or go/no-go items for the user (or cabinet lead), deliver them in **one** reply. Never open one question widget per item in a sequence.

## Shape

1. Short capsule (what this batch is).
2. Numbered list: `N. tag — one-line ask`.
3. **One** multiSelect widget (or one plain-text ask if a widget is wrong) covering every item. Options must be real choices; values read like natural replies.
4. Rejected / deferred items in one line if useful.

## Rules

- Wait for the pick before creating agents, writing skills, creating routines, or deleting anything.
- If cabinet protocol applies, send the same batch to the cabinet lead in the same turn, then wait for OK before implementing.
- Do not re-ask items already decided in this thread.

## Anti-pattern

Sending proposal 1 → wait → proposal 2 → wait. Batch first.
