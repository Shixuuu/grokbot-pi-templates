# Statement of Values (SOV) ⇄ ACORD 140

**Template rule:** fill only the user's OWN uploaded SOV template (e.g. from their wholesaler/MGA). Never bundle, download, recreate, or imitate any proprietary SOV file or layout, and never share one user's template with another. Without an uploaded template, output a plain generic SOV table/CSV labelled "GENERIC SOV — NOT A CARRIER TEMPLATE".

**COPE rule:** construction, occupancy, protection, and exposure data are never invented, estimated, or looked up from an address (no default protection class, no "typical" year built or area). Missing cells stay blank and go on the gap list with a client question.

ACORD 140 keys come from coi-autopilot-acord-140-field-map. **Header synonyms** (normalized phrases): loc_num: location number, location no, loc no, loc num, loc; bld_num: building number, building no, bldg no, bldg num, bldg; addr_num: address number, street number, house number, street no, address num, addressnum; street: street address, address line 1, street, address, addr; city: city; state: state code, state, st; zip: zip code, postal code, zip; occupancy: occupancy description, occupancy, occ desc; construction: iso construction, iso const, construction class, construction type, const class, construction, constr; year_built: original year built, orig year built, year built, yr built, yob; stories: number of stories, no of stories, of stories, stories, floors; sq_ft: square footage, square feet, building area, floor area, total area, sq ft, sqft; protection_class: iso prot class, protection class, prot class, prot cl, ppc; roof_year: year roof covering last fully replaced, year roof replaced, roof year, roof yr, roof updated; roof_type: type of roof covering, roof covering, roof material, roof type; sprinklered: sprinklered y n, sprinkler y n, sprinklered, sprinklers; sprinkler_pct: percent sprinklered, sprinklered percent, sprinkler percent, pct sprinklered; building_value: real property value, building value, building limit, bldg value, bldg limit, building; contents_value: business personal property, personal property value, contents value, contents limit, bpp value, bpp limit, contents, bpp; bi_value: business income, bi rental income, rental income, rental value, time element, bi value, bi limit, bi ee, rents, bi; valuation: building valuation, valuation, rc acv; coinsurance: coinsurance, coins; aop_ded: aop deductible, aop ded, aop; wind_ded: named storm deductible, wind hail deductible, wind deductible, wind ded; tiv: total insured value, total tiv, total value, tiv.

## Columns (one row per location # / building #) → ACORD 140 key
- `loc_num` / `bld_num` → `prem{n}_num` / `prem{n}_bld` (must match 125 and 140).
- `addr_num` (separate house-number column) + `street`, `city`, `state`, `zip` → `prem{n}_street` "street, city, ST zip". Physical address only, never a PO box/mailing address. Accept a period after the state and ZIP+4. No comma before the city → keep the whole string in street + CHECK "split the address" (or use the 125's split address).
- `occupancy` → `prem{n}_bld_desc` (+ `prem{n}_other_occupancies` for tenants).
- `construction` → `prem{n}_const_type`. **ISO crosswalk:** ISO 1 Frame · 2 Joisted Masonry · 3 Non-Combustible · 4 Masonry Non-Combustible · 5 Modified Fire Resistive · 6 Fire Resistive. Code → class = Medium + CHECK; class → code only when the template asks for an ISO code. Never infer either from a description (candidate from a description = Low + CHECK).
- `year_built` → `prem{n}_yr_built`; `stories` → `prem{n}_stories`; `sq_ft` → `prem{n}_total_area`; `protection_class` → `prem{n}_prot_cl` (never guessed); `roof_year` → `prem{n}_upd_roofing_yr` (+ roofing box X); `roof_type` → `prem{n}_roof_type`.
- `sprinklered` → `prem{n}_fire_type` ("Sprinklers"/"None"); `sprinkler_pct` → `prem{n}_sprinkler_pct` (percent rule).
- `building_value` / `contents_value` / `bi_value` → subject rows "Building" / "Business Personal Property" / "Business Income/Extra Expense" with `soi{m}_amount` (as stated; never rounded up).
- `valuation`, `coinsurance`, `aop_ded`, `wind_ded` → carried onto each subject row (`soi{m}_valuation`, `_coins`, `_ded`); SOV deductibles are usually *requested*: Medium + CHECK, a quote/binder/policy figure wins; wind % per the 140 skill step 4.
- `tiv` → not on the 140 (derived; step 6).

**Percent rule:** percent columns (% sprinklered, coinsurance, % deductibles) often hold fractions. A value with 0 < x ≤ 1 and no "%" sign means x × 100 ("1" = 100% sprinklered, "0.8" = 80%, "0.03" = 3%). Apply it both directions.

**One subject vocabulary** (140 subject text → SOV column, case-insensitive): building, bldg, real property → building; business personal property, BPP, contents, personal property, stock → contents; business income, BI, BI-EE, BI/EE, rents, rental value, rental income, loss of rents, time element, extra expense → BI.

Extra template columns (county, roof shape, flood zone, codes, alarms…): only stated facts; otherwise blank + gap list.

## Procedure
1. **Template (one-time column review, required for every template):** if the user uploaded their SOV template, read its header row and suggest a column map from the header synonyms above. Normalize headers (lower-case, # → "no", % → "percent", drop other punctuation); whole words only; exact header beats a longer phrase; short tokens (st, bi, loc) match only a whole header; reject a column whose first value doesn't fit (text in an amount column, a year that isn't 4 digits). **Show the suggested map as a table (generic key → header → first data value). Any value that doesn't fit its key is a FIX before you use the map.** Confirm the map with the user once (tap-to-pick: Looks right / Change a column, type-your-own) and save it with the template. The synonym list was partly tuned on one template family, so this one-time review stays mandatory for any other carrier's or wholesaler's template. Columns you can't map stay untouched.
2. **Intake → SOV:** one row per building. Cite the source line for every cell (Form = SOV, Box = column). Blanks → gap list + client questions.
3. **140 → SOV:** each premises/building block becomes a row (split the street into house number when the template has a number column, street, city, state, ZIP); subject rows map to building / contents / BI via the subject vocabulary; carry valuation, coinsurance, deductible; ISO code only if the template asks.
4. **SOV → 140:** each row becomes a 140 premises block; value columns become subject-of-insurance rows with amounts, plus valuation, coinsurance, and AOP deductible when the SOV has those columns (requested figures: Medium + CHECK; a quote/binder/policy figure wins). Wind/hail or named-storm % deductibles are recorded per coi-autopilot-acord-140-property step 4. An explicit $0 is a stated "not insured" and creates no 140 row and no gap. Causes of loss come from the notes or stay blank. Then finish the 140 with coi-autopilot-acord-140-property.
5. **Reconcile both ways** when both exist: address, area, construction, year built, values. Also compare coinsurance, valuation, and deductibles between the SOV (including cells above the header row) and the 140/quote. Read 140 Remarks for BI, rents, or wind-deductible requests that aren't in the premises block. Differences → CHECK (never silently overwrite). Required header cells in the template left blank (e.g. first named insured, effective date) → gap list.
   - **Conflicting duplicate columns:** if two template columns describe the same feature and disagree (for example roof covering vs roof deck, or two occupancy descriptions), fill neither from a guess. Copy each as stated and raise CHECK.
6. **TIV:** sum of the stated building + contents + BI (blank = not insured on that row, or missing: ask; explicit 0 = stated zero). Always compute it with the math. If the template has a typed TIV or a totals row that differs from your sum → FIX (e.g. "typed TIV is 1/10 of the sum: likely a missing zero"). If a value column holds text, TIV can't be computed → FIX. If the template has a TIV formula, let it calculate, and still compare.
7. Output: the field table, the filled user template (or the generic SOV CSV), the gap list, and the client question list. Close with the verification line from coi-autopilot-core-rules.
