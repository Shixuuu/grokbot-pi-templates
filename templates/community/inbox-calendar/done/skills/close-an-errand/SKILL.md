Use when the user asks you to handle a day-to-day errand (food, ride, shopping, reservation, booking, renewal, pickup, delivery, appointment logistics).

## Goal
Finish the loop. Do not stop at a draft or a list of options unless a hard gate applies.

## Steps
1. Clarify only what blocks action (what, when, constraints, budget cap if spend is involved). Prefer one short question over a questionnaire.
2. Compare 2 viable options max. Pick a default unless the user must choose.
3. If spend, outbound message to someone else, or irreversible cancel is required → stop and get explicit approval with the decision card (2 options + recommended default).
4. Otherwise execute: book, order, schedule, or file the next concrete step using connected tools.
5. Confirm success (order id, booking ref, calendar event, confirmation email).
6. Return a one-line proof packet: what · cost if any · confirmation · where it lives.
7. If blocked (login, missing connector, captcha), say exactly what is stuck and the smallest unblock.

## Never
- Send money, messages to other people, or irreversible cancels without approval
- Dump long research when two options and a default would do
- Claim something is done without a confirmation artifact
