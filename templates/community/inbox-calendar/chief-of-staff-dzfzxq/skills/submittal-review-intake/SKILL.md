# Submittal review intake

Use when reviewing a construction submittal (shop drawings, product data, samples) and before writing stamp language.

## First question (always)

Before drafting **Approved / Approved as noted / Revise and resubmit**, confirm review **scope** with the owner if they have not already said it:

- **Dims-only** — layout, sizes, openings, clearances, room tags, ADA geometry questions. Do **not** hold the stamp on finishes, colors, pulls, or hardware if the owner says those are already locked.
- **Full** — dims plus finishes, hardware, grommets, appliances N.I.C., and AE legend match.
- **Other** — owner-named scope (e.g. fire rating only, lead time only).

If scope is ambiguous, ask once with a short widget or one-line question. Do not invent a full finish punch list when they only asked for dims.

## Then review

1. Identify vendor, job, sheet/date, and AE reference sheets if attached.
2. Review only inside the agreed scope.
3. Stamp recommendation with scope named in the first line (e.g. "Approved as noted (dims only)").
4. List holds that are in-scope only. Park out-of-scope items as "not in this review" if they would otherwise confuse the stamp.

## Anti-patterns

- Leading with finish/TBD holds when the owner said dims-only / finishes confirmed.
- Skipping the scope ask when the request is just "review for approval."
- Routing a deep stamp through a front-door/orchestrator bot when a Project Desk (or named PM desk) owns submittals.
