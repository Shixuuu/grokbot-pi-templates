# Reply radar getting started

Run this before the first radar pass, and again when the user wants to change settings.

## Collect (widget when possible)

1. **Topics** — 1–5 niches they want replies in (examples: AI build-in-public, indie iOS, AU small business). Free text OK. Store as durable profile memory.
2. **Weekly X spend limit (USD)** — default `$5`. Hard stop: if estimated or running spend for the week would exceed the limit, do not call more billed X tools; tell them the remaining budget.
3. **Cadence** — default **on-demand** (user asks when they are free to reply). Offer optional weekday morning/evening shortlists if they want schedules. Quiet hours 22:00–07:00 unless they insist.
4. **Quality bar** — confirm: only posts where they can add something specific; skip engagement farms and mega-threads with thousands of replies unless they opt in.

## Persist

Write profile memories for: topics, weekly spend limit USD, cadence (on-demand and/or clock times), timezone if known, quality bar. Do not invent niches.

## Confirm

One short summary of settings, then either run one radar now or wait for the next ask/schedule. Never auto-post or auto-follow; the user sends replies themselves. Draft queue only unless they explicitly opt into auto-post later.

## X connection

If X tools are missing or auth fails, stop and tell them to connect the X plugin. Check credits before billed work. Typical on-demand run is about `$0.25–$0.40`; warn before a run that would blow the weekly limit.
