# Reliable X classroom publish

Use for signed-in x.com posting as the user. Goal: the tweet or reply actually goes live on time, once, with the intended copy — about the Real World Markets app, legally safe, clean.

## Guardrails
- One publisher at a time. If a compose lock exists and is younger than 8 minutes, do not start a second compose.
- Never type a long body or hashtags character-by-character. Paste or fill once.
- Click Post exactly once. If the button is sticky, wait for “Your post was sent.” Do not click again unless the composer is still open after ~3 seconds with the same clean copy.
- Never post a dirty draft (hashtag loops, “NaN” prefix, shell/terminal command prefix, extra/wrong images, empty box).
- Prefer desktop control when page-level browser tools fail or hang.
- Timebox ~3–4 minutes for a timeline post. If it is not live, stop and report failure — do not sit in compose.

## Clipboard / paste
- Never load the draft by selecting output from a terminal `cat` (or similar) — the shell command line can get copied into the tweet.
- Prefer: write draft to a next-draft file, then copy with a clean method so only prose hits the clipboard.
- Before Post: first visible line must be real classroom prose, not a shell prompt or command.

## Content
- Read the product-facts file when writing. Only claim live rooms/features listed there.
- Posts explain the app: Learn, DYOR look-up, Desk, World Circuit, Quote tree, Markets tape, Professor Moon.
- Legal fence: classroom not broker; LOOK DON'T BUY; delayed last; paper hypothetical; no profit/signals/urgency/pumps.
- Optional media: only official app media files or a fresh screenshot of OUR app. One image max. If media looks wrong, strip it and post text-only.
- When the live app changes, product-facts refresh must run before inventing new claims.

## Timeline post
1. Read the prewritten draft file. If empty, write unique copy from product facts first.
2. Open x.com compose (or a fresh composer). If a stale modal is open, close it and Discard.
3. Select-all, delete, then paste the full draft once.
4. Verify: first sentence is real prose, required URL present, hashtags appear once, media (if any) is intentional/official, no terminal junk.
5. Post once. Confirm the status URL.
6. Consume the draft, log URL + timestamp, release the compose lock.

## Replies
- Replies are not timeline posts.
- Cap 2 per handle per local day. Never the same parent twice.
- Skip pumps/signals. Always include the app link once. Prefer pointing people at a real room (Learn, Desk, Circuit, etc.) when it fits.
- Log parent URL + reply URL.

## After success
Ping the user with the live tweet or reply links. Never stay silent after a successful post. If posting fails, say so immediately.

## Do not
- Duplicate a slot.
- Boost.
- Attach unrelated or fake images.
- Fight another job for the composer.
- Invent app features that are not in product facts / the live site.
