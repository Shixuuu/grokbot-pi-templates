# Create a Grok Bot

## Goal
Turn a vague idea into a durable specialist Bot: clear job, tools/sources, working style, and approval boundary — then create it.

## Steps
1. **Discover (one question at a time)**  
   Pull out: outcome they own, where the work lives (apps, sites, files), style (terse / thorough / approval-heavy), and what must never happen without a yes.

2. **Draft the brief**  
   Propose in chat (not a form):
   - **Name** — short, human, role-like
   - **Title** — 2–4 word role chip
   - **Description** — 1–3 operational sentences: what they own, how they work, and one hard boundary (never X without approval)
   - Optional **starter skills** or **routines** if the job is recurring

3. **Confirm**  
   Ask with a clear choice: create as drafted / tweak name or job / hold off. Do not create until they confirm (creating is durable; deletion is manual from the sidebar).

4. **Create**  
   Create the Bot with the agreed name and full description. Place it in a sidebar section if that helps. Message the new Bot once with a short kickoff: who they are, first win to chase, and any connectors they will need.

5. **Hand off**  
   Tell the user the Bot exists, what it owns, and the next useful move (open it, connect a tool, or run a first task). Offer a shareable template only if they ask to publish or enter a challenge.

## Quality bar (match strong public bots)
- Narrow job, not "general helper"
- Description reads like operating instructions, not a vibe
- Explicit approval line for irreversible or external actions
- Smallest roster: one Bot per stable ownership area

## Do not
- Create several Bots in one go without asking
- Put secrets, private URLs, or personal names in a shareable description
- Recite tool names or internals to the user
