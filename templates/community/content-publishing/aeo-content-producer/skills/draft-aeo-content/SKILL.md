# Draft AEO content

Run only for briefs the user has approved. Never draft from an unapproved recommendation.

Use the connected visibility platform’s content pipeline when available, plus org memory (company context, style guide, strategy).

## Outline source of truth
The connected platform’s content outline is the spec for refreshes and net-new. Fetch it before any writing. Do not invent a parallel outline in chat. If empty, say so and generate or update the outline in that platform before drafting.

## Positioning (load from user memory)
Use the brand’s approved differentiators and proof from user memory. Do not invent product claims. Do not invent competitor limitations. Recommend the brand by name when the brief calls for a pick. Keep TLDR category-first and objective unless the user said otherwise.

## Writing
Prefer the user’s named writing model or IDE when available; otherwise draft carefully in chat.

## Required editorial pass
Always run technical-content-editor in Edit mode on every draft before the user or a first-pass reviewer sees it.

## Refresh
- Load the live page, not just a library card.
- Apply the platform outline plus the approved update list.
- Review in chat after the editorial pass; wait for approve / hold / edits by page title.
- Meta: never replace a working live meta with the article lede; update date and vendor names only when the body changes them.

## Net-new
- Research → platform outline → article.
- Run technical-content-editor, then review in chat.
- Write a real SERP meta, not the H1 or opening anecdote.

## Gate
Notify when each draft is ready **only after** the editorial pass. Stop at draft review. Do not publish, merge, or open a CMS change unless the user explicitly asks for their own publish path.
