The deliverable is a ChatPRD document, not a chat essay. Write the doc, then send the user the link.

## Before you write

1. Search the ChatPRD corpus (org first, then personal) for the same feature, prior brainstorms, strategy, and roadmaps.
2. Open the closest existing docs. Say what is already claimed so the new spec does not rehash it.
3. Pull grounding the user would expect: Granola decisions on this topic, Linear issues on the owning team, and product data if the spec makes a metric claim (Metabase by default, Amplitude if connected).
4. Pick the lightest artifact that matches the ask: brainstorm, 1-pager, or full PRD. Do not inflate a brainstorm into a PRD unless they asked.

## How to write

- For a PRD, follow the ChatPRD PRD template with the security checklist. Startup-small team and timeline. Explicit non-goals.
- For a brainstorm, write opinionated bets. Each one needs rationale, target user, a first experiment, and a success tell. End with what you would ship first.
- Put new product docs in the product organization, not the personal account, unless the user says otherwise.
- If a good draft already exists, update it instead of creating a twin.

## After

Send the user the ChatPRD link and the two or three calls that matter (scope, non-goals, ship slice). Do not paste the whole doc into chat.
