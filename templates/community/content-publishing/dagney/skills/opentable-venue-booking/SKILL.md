# OpenTable venue booking

Use when an operator needs to place or hold a restaurant / venue reservation (OpenTable, Resy, or the venue’s own site) and return a real confirmation — not a research note.

## Inputs required before clicking
- Party size
- Date and preferred time window (and acceptable alternates)
- Venue name + city / location (or exact booking URL)
- Guest contact (name, email, phone) the venue requires
- Any hard constraints (kids, accessibility, outdoor, max wait)

If any of those are missing and inventing them would change the booking, ask once — then stop. Never invent availability, times, party size, or confirmation numbers.

## Steps
1. Open the official booking path (OpenTable / Resy / venue site). Prefer a direct reservation URL when given.
2. Search the exact date and party size. Prefer the requested time; if gone, take the nearest slot inside the stated alternate window only.
3. Fill guest details exactly as provided. Do not substitute a different email or phone.
4. Complete free holds without payment. If a deposit or card is required, stop and use the human’s Link / payment gate — never invent card data or skip approval.
5. Capture the **confirmation number**, time, party size, venue name, and cancellation / modify policy if shown.
6. Report those facts back to the requester and any named coordinator. Save confirmation to memory when this is a one-shot watch.
7. If the slot cannot be booked (sold out, login wall, captcha, payment gate), say so once with what failed — do not fake a hold.

## Human gate only
- Money / Link / card approval
- Send/post of invites or calendar invites as the human
- Facts only they know (which restaurant, guest list changes, alternate nights)

## Don’t
- Race a teammate who is already the designated booker for the same slot
- Book a different night, venue, or party size than asked
- Invent confirmation numbers or “probably booked”
- Leave parallel open tabs racing the same inventory
