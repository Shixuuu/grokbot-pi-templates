# 크몽 근거형 전자책

성공담·수익보장 상품이 아니다. 공개 사례·법령·공식문서를 직접 확인하고, 출처 URL과 워크북을 붙여 파는 실무 가이드다.

## 한 편의 구성

본문 40~60p가 기본(로드맵형은 예외적으로 더 길 수 있음). 항상 이 뼈대:

1. 표지 — 한 줄 반전 제목, 근거 종류, 확인 월
2. 면책 — 세무·법률·플랫폼 정책이면 본문 1페이지에 필수
3. 프롤로그 — 독자가 검색한 오해 → 이 책이 확인한 것
4. 결론 표 — 책을 다 읽기 전에 핵심 + 근거 열
5. 1부 사실/사례 (실패·리스크를 수익 사례만큼)
6. 실행 장
7. 워크북 — 빈칸·표·체크리스트. 읽기만 하는 요약 금지
8. 부록 A 검증 로그 + 출처 URL 전체
9. 부록 B 출처의 성격(이해관계)
10. FAQ, 용어

표시 규칙: 모든 주장에 근거 등급. 출처 없는 단정 금지. 자료가 충돌하면 숨기지 말고 표시.

등급은 주제에 맞게 고른다. 예: `[공식]/[2차]/[해석]`, `[법령]/[공공]/[민간]/[해석]`, `[지침]/[사례]/[해석]`, `[법]/[공익]/[전문가]/[약관]/[해석]`.

## 문체

합니다체. 짧은 문단. 한 문장 사실 다음에 한 문장 의미.
저자 개인 성공담으로 팔지 않는다. "확인된 것 / 확인 못 한 것"을 가른다.
제목·표지에 월수익 숫자("월 100만원")를 약속처럼 넣지 않는다. 사례에 나온 숫자라도 본문에서 사례 번호와 함께만.

금지 표현: 최대/최고/최초/제일/유일, 100% 환불, 무제한, 평생, 승인 보장, 안 걸리는 법, 회피, 절세 노하우, 공인·제휴처럼 읽히는 상표 사용.
외부 연락처(전화·메일·SNS·홈페이지) 본문·상세·안내에 넣지 않는다.
"이런 분께 맞습니다 / 맞지 않습니다"를 상세페이지에 둘 다 쓴다.

## 산출 패키지 (빠지면 미완성)

폴더 `N/` 아래를 항상 이 형태로:

```
N/files/
  NN-slug-00-listing-info.txt
  NN-slug-01-checklist.txt
  NN-slug-02-main-652x488.png
  NN-slug-03-preview1-toc.png
  NN-slug-04 ~ 07  미리보기 2~5
  NN-slug-08-ebook-XXp.pdf
N/files.zip
```

보강 규칙:

- 파일 접두사 `NN` = 폴더 번호 `N`. 어긋나면 다시 맞춘다.
- `files/` + `files.zip` 둘 다. 등록정보·체크리스트 없이 PDF만 두고 끝내지 않는다.
- 페이지수 4자 일치: PDF 실제 쪽수 = 파일명 `XXp` = 등록정보 = 메인이미지 "N페이지".
- 폴더에 `확인일.txt`를 따로 둔다. listing 안에만 묻히지 않는다.

## 등록정보.txt 필드

카테고리, 서비스 제목, 가격(패키지 OFF·단일), 목차(50~999자, `<`와 백틱 금지), 키워드 5개(각 20자), 결제 후 안내(300자), 상세페이지.

가격대: 정책·실무 가이드 12,900원 / 사례분석·공식문서 가이드 14,900원 (VAT 포함). 리뷰 쌓인 뒤 인상은 listing에만 메모.

상세페이지 뼈대: 오해 한 줄 → 이 책이 확인한 것 → 들어 있는 것 → 워크북 → 표시 규칙 → 맞는 사람 / 안 맞는 사람 → 12개월 개정판 재발송.
세무·법률이면 상세 첫 줄과 결제 후 안내에도 면책.

## 크몽 에셋

- 메인: 정확히 652×488. 흰 배경, 검은 제목, 노란 밑줄 한 곳, 상단 검정 뱃지(주제 | 근거 종류), 가운데 지표 4칸, 하단 출처 공개 + 페이지수. 생성형 실사 표지 쓰지 않는다.
- 미리보기 5장, 한 장씩, 블러·모자이크 금지.
- 1번은 반드시 실제 목차 페이지. 부 표지·빈 구분 페이지 금지. 정보 밀도가 낮으면 다른 본문 페이지로 교체.
- 미리보기는 PDF 페이지 캡처, 약 1240×1755.
- PDF는 STANDARD 칸만. 패키지 OFF.

## PDF 제작

HTML → wkhtmltopdf → A4 (595×842 pt). 본문 페이지를 생성형 이미지로 만들지 않는다.
워크시트는 채울 칸(밑줄, 빈 표, 체크박스)이 있어야 한다.

## 부록 A 검증 로그 (기본, 예외 없음)

URL 나열만으로 끝내지 않는다. 유튜브 편 방식을 표준으로:

| 항목 | 출처 | 확인 방법 | 교차검증 | 확인일 |
| 주장 한 줄 | 원문 URL | 해당 문단/조문 | 됨/안 됨 | YYYY-MM |

교차검증이 안 된 항목은 안 됐다고 쓴다. 확인일은 본문·상세·로그가 같아야 한다.

## 반려 방지 + 출고 게이트

출고 전 전부 통과해야 한다:

- 패키지 파일 8종 + zip + 확인일.txt
- 목차 미리보기 1번이 진짜 목차
- 페이지수 4자 일치
- 금지어·외부연락처·수익보장 없음
- 모든 숫자에 사례번호 또는 조문
- 세무·법률·정책이면 면책 3곳(본문 첫 페이지, 상세, 결제 후 안내)
- 자격처럼 읽히는 표현 없음 (세무사, 변호사, Anthropic/구글 공인)
- 특정 판매자·법무법인 실명 비방 없음

## 출고 후

정책·플랫폼 문서는 분기마다 원문 대조. 세법은 매년 1~2월.
바뀌면 개정판 PDF + 목차·페이지수·확인일 갱신 후, 약속한 12개월 동안 구매자에게 재발송.
개정 기간은 "평생/무제한"이 아니라 "12개월간"으로만 쓴다.
