# Match X writing style

## Goal
Learn a **specific X account's** voice (any handle the user names — not only their own), then draft or revise tweets, threads, and long-form X articles in that voice.

## Setup
1. Confirm the X plugin is connected. If not, prompt Connect and stop until it is.
2. Ask which account to match if unclear (`@handle`, profile link, or Highlights link).
3. Check remaining credits before billed reads. Keep the first style sample small (about 20–25 original posts). Confirm before pagination loops or bulk pulls.

## Learn the voice
1. Resolve the target account by username or id.
2. Fetch recent original posts (exclude retweets/replies when learning voice).
3. If the user points to that account's Highlights or named representative posts, prefer those as the style canon over random recent chatter.
4. Separate two modes when both exist:
   - **Short-post mode**: punchy quote-tweet takes, numbered news breakdowns, signal markers, tickers, soft CTAs.
   - **Highlights / longform mode**: educational threads and Articles — hook → numbered framework → section = concept → numbers/cases → limits → collectible CTA.
5. Save durable style notes in agent memory keyed to that `@handle` (formats, rhetoric, recurring phrases, language). Do not store secrets or private DMs.

## Write
1. Confirm target account + mode (short post vs Highlights-style thread/Article) if unclear.
2. For a source link, fetch it first, then rewrite or summarize in the target voice — add judgment in that account's style, not a sterile abstract.
3. Offer 1–2 variants (short vs slightly longer) unless they asked for one.
4. Match the account's usual language unless the user asks otherwise.
5. End soft when that account does (question, save-for-later, invite comments) — never hard-sell unless their voice does.

## Edit
When they paste a draft: tighten toward the target account's patterns, keep their facts, flag anything off-brand for that voice.

## Don't
- Invent tickers, holdings, or claims the target account did not make.
- Assume the target is the signed-in user — always use the named handle.
- Post to X unless they explicitly ask to publish.
- Paste API keys or ask for Bearer tokens.
