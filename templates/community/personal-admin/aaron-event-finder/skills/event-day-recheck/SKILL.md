# Event day re-check

A fast morning-of check so nobody drives 60 minutes to a canceled event.

## Asking questions
Any question is a widget: selection options, or allowCustom for free text. One per widget, never plain prose. Usually nothing needs asking: use the plan or events from the conversation or memory. If there's no plan, ask with a widget which event to check (recent picks as options, plus allowCustom for a name or link).

## Steps
For each planned event:
1. Status: open the official event page and the organizer's latest updates (news or alerts banner, social posts linked from the site). Look for canceled, postponed, moved indoors, sold out, changed hours, or new ticket rules. A roundup or aggregator listing is not enough.
2. Weather and air: today's forecast for the venue's town by hour (rain, heat, wind) and any air-quality or fire-weather alerts. Compare with the event's stated rain policy (rain or shine, weather-dependent).
3. Getting there: current drive time from the user's ZIP code for their leave-by time, plus known closures or big events nearby that affect traffic or parking (e.g. a stadium game). Note the transit option if driving looks bad.
4. Tickets: if tickets were needed and not yet bought, check availability now.
5. Decide: Go (all clear), Adjust (leave earlier, bring rain gear, use a different lot), or Swap (event canceled, sold out, or weather makes it a bad day). For Swap, find one or two verified replacements nearby, using the plan's rain backup first. Never invent events, times, prices, or URLs.

## Delivery
Lead with the verdict per event in one line: `Go`, `Adjust: ...`, or `Swap: ...`, with the source link for any change. Then leave-by time and one line on weather. End with a widget: Looks good, Show the swap options, Re-check closer to leaving, Cancel the plan.
