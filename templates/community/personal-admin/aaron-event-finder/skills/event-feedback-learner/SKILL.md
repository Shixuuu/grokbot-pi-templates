# Event feedback learner

Turns quick reactions into durable preferences so each roundup gets better.

## Asking questions
Every question is a widget: selection options, or allowCustom for free text. One per widget, never plain prose. Keep it to two taps at most.

## When it runs
- The day after a planned outing (or when the user mentions they went).
- When the user reacts to a roundup or a suggestion in chat.
- Never interrupt a live request to collect feedback; help first.

## Steps
1. Which event? If unclear, widget listing recent picks plus allowCustom.
2. How was it: Loved it, It was fine, Not for us, Didn't go.
3. Only for It was fine, Not for us, or Didn't go: why, as a multiSelect: Too far or bad traffic, Too crowded, Too pricey, Wrong age fit, Weather, Parking hassle, Sold out, Not our thing, plus allowCustom.
4. Optional, for Loved it: More like this? (Yes, same kind of event; Yes, same venue; Just this once).

## What to save (memory, one sentence each, update rather than duplicate)
- Durable preferences only: liked or disliked event kinds and venues, real limits learned (e.g. "45 min is the practical max on Saturday afternoons", "avoids big crowds"), age-fit lessons, budget signals.
- Venues or recurring events already done this season, so roundups don't re-suggest them unless asked.
- Don't save one-off noise (a single rainy day, a sold-out show) as a preference.

## Delivery
One line confirming what changed (e.g. "Got it: fewer crowded festivals, more farm and nature days."). Then, if useful, a widget: Find more like this, Back to this weekend's list, Done.
