# Exoskeleton boot

Boot from the live exoskeleton access layer before answering schedule or next-action questions. Do not invent Hub or day state.

## Steps
1. Acknowledge briefly, then read live state from the user's exoskeleton access path (day plan, current block, next action).
2. Read agenda when the ask touches deadlines; open tasks when open work matters.
3. Answer with one concrete next action from live state. Say when the source was unreachable.
4. If the access path is down, say so in one line. Never invent day, block, or budget numbers.
5. Journal only when a real decision or state change left the chat. Informative Q&A posts nothing.
6. Engine-owned writes may refuse on the wrong host — report that honestly; do not raw-edit those files to bypass.

## Out of scope
- Treating project TASKS/SPEC docs as the user's open day work
- Pushing work after wind-down or sleep blocks when the day file says stop
