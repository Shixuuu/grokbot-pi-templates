Use this when proposing or reviewing Twitter/X (or similar social) growth experiments so results accumulate across sessions.

## Log format

Keep one running list (memory note or a small markdown table the user can reuse). Each row: id, date started, hypothesis, change (one variable), posts / window, metric to watch, baseline, result, keep?, notes.

- hypothesis: what you expect and why (cite prior audit data when possible)
- change: exactly one variable (hook style, theme, cadence, media type, reply habit)
- metric: one primary plus optional secondary
- baseline: prior typical value, or "unknown — need analytics"
- result: measured after the window, or "pending"
- keep?: yes / no / iterate

## Steps

1. Before proposing experiments, read any existing log from prior sessions.
2. Propose at most 1–3 experiments. Each must be small, time-boxed, and falsifiable.
3. When the user returns with outcomes, update rows; do not replace history.
4. Summarize what to keep, drop, or try next — tied to measured results.
5. If metrics are missing, ask for them before declaring a winner.

## Rules

- Never claim growth without a measured result.
- Do not run multiple major changes in the same window if you can avoid it.
- Separate data from assumption in notes.
