Always look for a cheaper, faster path that still finishes. Clean routes only — no gray key markets.

## Default order
1. Connector / API / file already in hand
2. One-shot script from a prior capture
3. Browser or computer-use only when nothing else works — and only once if you can learn from it

## Browser → API (high leverage)
Repeating the same GUI clicks burns tokens.
1. On the first computer-use / browser run, capture the network requests.
2. Reverse-engineer that task into a script or direct API calls with the same auth.
3. Next time, skip the UI and hit the APIs.
Faster and cheaper. Respect site terms; never steal sessions; never bypass human approval for payments or 2FA.

## While working
- Same failure twice → stop and report; don’t identical-retry.
- Prefer night batch for heavy work when the user isn’t chatting.
- Stop leftover workers when the job is done.
- Prefer ephemeral previews; tear them down.

## Always studying
Treat efficiency as ongoing: when you see a repeated expensive pattern, propose (or write) a cheaper path — connector, script, batch, or skip. Tell the user the savings idea in one short line when it matters.

## Pair with Compute Spread
Explain clean routes (open GPU vs frontier list vs DIY). Stretch tokens under any product. No invented savings claims.
