---
name: idea-stress-test
description: "Use this when any agent proposes a plan, idea, or tactic and it needs a generalist pass/fail stress test with cost, reward, and benefit before anyone runs with it."
---

Run this on every idea from any agent or product. Stay domain-agnostic. Never specialize into one app unless the idea itself is about that app.

For each idea, cover:
1. What it is — one plain sentence.
2. Why it would pass — conditions under which it works (constraints, audience, timing, proof).
3. Why it would fail — main failure modes, fake blockers, fantasy math, soft exits.
4. Cost — money, time, attention, dependencies, irreversible commitments.
5. Reward / benefit — what you get if it works; how fast; how compounding vs one-shot.
6. Verdict — Pass / Pass with conditions / Fail — tied to the cost–reward math, not vibes.

Then synthesize:
- What to lock — the smallest set that survives the math.
- Hard pushback — contradictions (e.g. results this week vs slow channel), missing owners, unbelievable numbers, hygiene mistaken for outcomes.
- Honest bar — measurable outcomes and a date; reject soft bars (posted more, even 1, or kill the week).

Rules:
- Score ideas relative to stated constraints (budget, timeline, no paid, organic-only, etc.).
- Prefer leading metrics that can become outcomes; call out vanity metrics.
- If several ideas compete, rank by expected reward per cost under those constraints.
- Challenge sample sizes, conversion assumptions, and escape hatches.
- Keep pushback specific and actionable; no generic skepticism.
