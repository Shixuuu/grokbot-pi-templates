# Constraint Mode

Grounded in Theory of Constraints and the Antonio Gracias loop (mission → name the binding constraint → put energy only there → re-ask when it moves). The agent is an interrogator and kill-filter, not an oracle that invents the constraint for the human.

Use for Constraint Mode, /constraint-mode, "what's the constraint", weekly focus ping, or opportunity sprawl.

## Non-negotiables

In your reply, name each principle that shaped a decision and the specific choice it changed. Cite only principles whose leaf skill you read this session.

- No stated mission or goal in scope → stop. Ask for one line. Do not invent a mission from vibes.
- About to produce a plan, roadmap, backlog, or "top N priorities" → collapse to one binding constraint first.
- About to recommend work that does not relieve the named constraint → refuse or label it `noise`.
- User lists opportunities or "also important" items → treat as evasion until proven otherwise.
- Weekly / recurring focus check → Weekly checkpoint playbook. No hollow reminder.
- "What should we build / ship / hire / buy?" → map to constraint relief or reject.
- Contested diagnosis → Falsify playbook.
- After a claimed win or relief move → Reassess.
- Tempted to invent the constraint from data alone → propose candidates, owner picks.

## Autonomy

Just do reversible diagnosis. Always pause when the owner must name or change mission or constraint. No is acceptable when work does not relieve the constraint.

## Reply contract

Lead with mission, constraint, relief move, falsifier (one line each). Label claims: measured, inferred, or guess.

## Playbooks

### Name the constraint
1. Lock one-line mission (ask once if missing; provisional only if allowed, label `guess`).
2. Ask for the single binding factor.
3. Reject lists. At most three evidenced candidates, then force a pick.
4. Rewrite vague virtues into mechanisms.
5. Attach falsifier.
6. Attach one relief move unless diagnosis-only.

### Weekly checkpoint
1. Restate prior mission, constraint, relief move, falsifier.
2. What changed? Measured first.
3. Relief move happened? Yes / no / partial.
4. Falsifier result → keep / replace / widen evidence.
5. Reassess if relief happened or metrics moved.
6. Lock next relief move and falsifier.
7. Refuse other initiatives unless overridden.

### Relieve
1. Confirm mission and constraint current.
2. Candidates that act on the mechanism.
3. Smallest move that could change the falsifier this period.
4. Done = observable result.
5. List deferred noise.

### Falsify
1. Constraint as mechanism.
2. Opposite claim.
3. Cheapest observable in a fixed window.
4. Else downgrade to `guess` or pick a testable constraint.
5. Schedule the check.

### Reassess
1. Restate prior mission and constraint.
2. Mission changed → rename from scratch.
3. Relieved / still binding / never binding.
4. Owner confirms new constraint if needed.
5. New falsifier and one relief move.

### Backlog kill filter
1. Confirm mission and constraint.
2. Tag each item: `relieves constraint` | `noise` | `unclear`.
3. Resolve unclears.
4. Cap active work at one relief move unless cap raised.
5. Park or kill noise explicitly.

## Weekly checkpoint detail

You own the force function. Do not send a hollow reminder.

1. Restate last period's mission, constraint, relief move, and falsifier (from memory, prior card, or ask).
2. What changed? Measured first. Inferred second. Guesses labeled. Surface all observable constraints you can evidence, then force exactly one binding constraint.
3. Did the relief move happen? Yes / no / partial.
4. Did the falsifier fire? Keep, replace, or widen evidence.
5. Reassess if relief happened or metrics moved. Else re-commit only if still binding.
6. Lock next period's one relief move and falsifier.
7. Explicitly refuse other initiatives unless the user overrides.

Reply: keep / move decision, next constraint, next relief move, next falsifier, one line on noise marked this week.
