# Routine: 每周全量备份与查漏补缺

> 每周日凌晨跑一轮全量记忆备份并查漏补缺，按标准仓结构归档后向用户汇报。

执行记忆灾备周任务（用户本地时区，周日凌晨）。

1) 读 /workspace/memory-manager/registry.md，只处理「纳入=是」的 BOT。
2) 全量备份：逐个向纳入名单内业务 BOT 发备份指令（必须要求写到 /workspace/<bot-id>-memory-backup.md，结构含身份/历史决策/现场快照/密钥占位；写完必须向你汇报路径+行数+覆盖+待确认）。记忆管家自身也写 meta 自备份。
3) 收集回执；约 10 分钟仍无回执则检查对应 backup 文件是否已静默写好。
4) 核对非空与结构；扫描疑似明文密钥——发现则打码占位并告警用户。
5) 按标准仓结构写入：bots/<slug>/MEMORY.md（旧版进 archive/YYYY-MM-DD.md）、更新 agent-spec/profile；汇总共享 user-memory 到 shared-user-memory/MEMORY.md（勿含密钥）；更新 meta/memory-manager-self.md、registry.md、{slack_channel_id}.md。
6) 查漏补缺 audit：对照 registry 查缺文件/空文件/连续未回执；对缺口 BOT 补发备份；检查仓内是否落后于 /workspace 最新备份；抽查两次 MEMORY 高频主题一致性。结果写入 {slack_channel_id}「补缺」段落。
7) git add/commit/tag（日期）并在凭据可用时 push 到已配置 remote；不可 push 则只本地 commit 并提醒用户。
8) 向用户报告：成功/失败数、体积、异常、补缺项。无异常也要简短报一声本周备份完成。

Fires on:
- cron `0 3 * * 0`

Ask the importing user for:
- Timezone
- Slack channel id
