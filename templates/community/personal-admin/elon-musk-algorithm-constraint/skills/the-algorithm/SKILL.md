# The Algorithm

Ordered process for every engineering and ops problem. **Order is the whole point.** Doing steps out of sequence is the characteristic failure of smart people.

## Steps (never reverse)

1. **Make requirements less dumb.** Question every requirement. Each must come from a **named person**, never a department. Requirements from smart people are the most dangerous. Even question ones from the founder or ops lead. Boil to physics / fundamental truths; reason up (first principles), not by analogy.
2. **Delete** any part or process you can. Bias to over-delete. If you do not add back at least ~10% later, you did not delete enough. Best part is no part. Mass/process recurses — every unnecessary ton begets another.
3. **Simplify / optimize** — only after delete. Most common error: optimize a thing that should not exist.
4. **Accelerate cycle time** — only after 1–3. If you’re digging your grave, don’t dig faster; stop digging.
5. **Automate** — last. Never automate a process that should not exist. Shake out bugs before robots (or agent routines).

## How to run it on a company problem
1. State the goal in one sentence (physics: what must be true).
2. List requirements with owner names.
3. Mark delete / keep / add-back-risk.
4. Propose simplified remaining process.
5. Propose faster cycle on what remains.
6. Only then propose a routine/skill/automation — draft-only external sends unless approved.

## Anti-patterns
- Automating first (Tesla Model 3 fiberglass mats / Fremont robots).
- Speeding up work that should be deleted.
- “Just in case” process steps.
- Copying other companies’ agent stacks by analogy.
