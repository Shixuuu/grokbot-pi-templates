# Virtual closet

Day-to-day filing for the user’s own closet.

## Custom sections

The standard setup covers the user's own closet only. Status lanes (Incoming, Order Complete, Returns, Shopping Favorites or a Style Journal) and order tracking are not standard features. Add one only if the user asks for it as a custom section, and keep it in its own file, never mixed into the closet.

## Categories

Owned Closet pages: Dresses, Tops, Skirts, Pants, Jackets, **Shoes** (sections by type: Sandals, Heels, Boots), Accessories (sections: Hats, Scarves), Purses, Jewelry (sections: Necklaces, Earrings, Bracelets) (plus Formal as needed).

SKU letters: D dresses · T tops · S skirts · P pants/bottoms · J jackets · **H shoes** · A accessories (hats, scarves, purses) · JW jewelry. Layered jewelry looks get their own codes: NS layered necklace stacks, BS bracelet stacks (listed by the JW pieces in them).

## Daily flow

1. New photo / isolate arrives → describe → assign SKU → create folder + `item.md` → rebuild that category page → show the user the asset + page
2. User locks brand/name (“it’s X”, “call it Y”) → update `item.md` + rebuild — don’t invent brands
3. Packing / outfit asks → pull from Closet by category + Style File occasions + climate (layers for cold hotels, open sandals in heat, etc.)

## Labeling when brand/name is missing

1. Plain-words description (silhouette, neckline, sleeve, length, fabric look, print, hardware)
2. Propose a style-only display name (color stays in the Color field)
3. Ask once: brand if known, favorite or not, size note
4. File folder + isolate + square crop + item note
5. Rebuild page; show tile + page for lock

## Fit rules

Live on the item and in a short size note (e.g. “never dress size 8; this heel runs small — try 8.5”). Brand size charts beat a single number. Update when an outfit or fit teaches something new.

## Ask first

- Category
- Brand / name if they know it
- Any set pairing (hoodie + shorts)
