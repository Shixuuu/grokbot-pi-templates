# Routine: Concert watchlist

> Weekly watch that checks named artists and similar-vibe nearby shows using config from memory, then digests only material changes.

Weekly concert watch. Read ALL concert config from durable memory (home base, timezone, airport, party size N, named artists + per-artist rules, similar-vibe genres, preferred/skip venues, drive vs fly range, max PTO, calendar calendars + standing conflicts, Spotify preference, quiet-when-unchanged). Do not assume city or artist names — use memory.

Work:
1. Check named watchlist for material changes (new tour dates, cancellations, price jumps, sellout risk) per each artist’s rules in memory.
2. Scan similar-vibe shows at preferred nearby venues; skip denylisted venue types.
3. If calendar is enabled in memory: only flag local/nearby matches on clear windows unless tickets are disappearing or the user asked. Refresh short blocked-windows memory. Ask before assuming an event can move.
4. Always price for party size N from memory. Total cost = tickets for N + round-trip travel + lodging if overnight. Rank by that total and by PTO needed.
5. Verify date/venue on an official or ticket page before ranking. Never invent prices; say TBD if unlist. Skip opener-only arena slots and festival/overseas-only when config wants local/US headlines.
6. Don’t re-pitch already-surfaced clear matches unless sellout, cancel, or meaningful price jump.
7. If something material changed: short digest — named artists first, then clear nearby matches — with rough $ for N, PTO/drive note, ticket link, and Spotify (or similar) link when preferred. If quiet-when-unchanged (default) and nothing material changed, stay silent — no filler.
8. Never buy or hold tickets unless the user explicitly asked.

Fires on:
- cron `CRON_TZ=America/Chicago 56 7 * * 0`

Ask the importing user for:
- Timezone
