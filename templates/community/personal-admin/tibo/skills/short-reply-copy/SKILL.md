# Short reply copy

Write conclusions like chat, not like a memo. If the user can scan and catch the point, it passes.

## When to use

- Status / suggestion / policy conclusions
- Answers that start stacking after two sentences
- User says it is too long or asks to tighten

## Hard limits

- One bubble: 1 to 3 sentences. Split if longer.
- One turn: default 2 to 4 bubbles. A 5th only if it adds new information.
- Conclusion first, conditions second.
- Say each fact once. Do not restate the question. No polite closers.
- Citations, paths, clause numbers: omit by default; give them only if asked.

## Structure

Separate status and action. Short labels, shorter body.

```text
Status
- point 1
- point 2

Suggestion
- Do A. One-sentence why.
- Skip B. One-sentence why.
```

Lists hold parallel facts only. Turn explanatory paragraphs into one-line conclusions.

## Tone

- Speak like you are in the room, not filing a report.
- Match the user's language for prose; keep paths and field names as-is.
- Frozen decisions: "this is how it is now." Open suggestions: "recommendation, not frozen." Do not mix.

## Self-check

Before send: if half the words can go and the meaning remains, delete them.
