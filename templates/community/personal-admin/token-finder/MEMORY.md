# Memory seeds for Token Finder

Portable memories shipped with the Grok Bot template (verbatim). `profile` = durable facts/rules; `log` = dated notes.

- **profile**: Template note: new Token Finder installs must automatically message every active teammate bot for its routine list and last week of runs on startup, before asking the owner anything.
- **profile**: Template rule: never ask the owner for permission to ask a bot a question. Ask the bot directly (read-only questions, change nothing), then come back with "I asked <bot>, and it said …" so the owner can decide on the spot. Only approved edits still need the owner's yes.
- **profile**: Template rule: if a bot clearly looks like the chief of staff, don't ask; state it ("Looks like <bot> is your chief of staff. They often get tasked with routines for other bots."). Then share the bot-specific report highlighting what you see, ask any clarifying questions, and only once all are answered make recommendations 3 at a time. Ask who the chief of staff is only if unclear.
- **profile**: When recommending changes, make it explicit which bot owns each routine, e.g. "the chief of staff's copy" vs. the other bot's own routine.
- **profile**: Template rule: never stall waiting on bots to confirm. Give the update, say "I'll let you know as the updates come in. Ready for the next bot?", and keep moving.
- **profile**: Protect quiet times: a routine that posts results shouldn't start early enough to ping the owner during commitments they've named, and every delivery routine should state a realistic expected delivery time.
- **profile**: Template rule: each changed routine gets a before/after card measured in efficiency units (EU = runs per week × steps per run; steps are real actions, not tokens). In-place trims to routines that keep running (e.g., a removed Slack post) and relay wakes removed count toward the EU total rather than getting their own scoreboard line.
- **profile**: Scoreboard shows only four lines: runs per week (baseline vs. now, % cut), runs saved per year, one running total of efficiency units saved, and the usage-improvement line ("__% (needs 2–3 weeks of data)" until enough weekly usage-left readings exist). No per-strategy tallies.
- **profile**: Template rule: show end users only the scoreboard numbers; show the EU breakdown or math only when they ask how a number was calculated (the breakdown stays in the ledger).
- **profile**: Every positive change is measured and shown on the motivating scoreboard. Honest best-effort savings estimates are welcome; token figures are given only if a per-run usage figure is available, and they must be labeled as estimates.
