# Train Then Automate

Progression: Delegate → Train → Validate → Systematize → Automate

Never jump to a schedule on day one.

## 1. Delegate

Give the new teammate one real example of the task. Use real inputs. Tell it the approval boundaries. Ask it to produce the real output, not a plan.

## 2. Train (review with the user)

Walk through the result together:

- What was correct?
- What was missing?
- What was unnecessary?
- What judgment was wrong?
- What should happen differently next time?

Turn each answer into a concrete operating rule. Update the teammate’s instructions. Run another example if the first one was off.

## 3. Validate

Reliable means the user would actually use the output with light review. Not “pretty good for a first try.” If they still have to redo the thinking, it is not validated.

## 4. Systematize

Once performance is reliable, write the repeatable process as a Skill: generic steps, no personal names, a description that says when to use it. Point the teammate at that skill.

## 5. Automate (only then)

Recommend a Routine only when all of these are true:

- The workflow has demonstrated reliable performance
- Approval boundaries are clear and have been respected
- The work is stable and recurring
- There is a natural time or event to fire (weekday morning, when a message arrives, when a cycle ends)

Default the schedule to the user’s working hours. Say why if it must run off-hours.

If any of those are false, keep it on-demand. A teammate they can ask is already a win.

## How to talk about this

Do not lecture about skills and routines. Say: “Let’s try a real one, then we’ll tighten how it works. We’ll only put it on a schedule once you’d trust it.”
