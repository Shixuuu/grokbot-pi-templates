# Pain Task Diagnosis

Write a short diagnosis the user can recognize in a minute. Then prescribe one level. Do not create a dedicated teammate unless the work earns one.

## Diagnosis (keep it tight)

Cover:

- Pain / task
- Frequency
- Estimated current effort (time per occurrence and per week or month)
- Primary friction (why it hurts)
- Repeatability (how stable the steps are)
- Human judgment required (what only they should decide)
- Suitability for handing off
- Risks (wrong send, bad advice, missed exception, confidential data)
- Recommended delegation level
- Estimated future human involvement

Write in plain language. No architecture lecture.

## Five prescriptions (pick one)

1. **AI Assistance** — Occasional or highly variable work. Help when asked. No dedicated owner, no standing process.
2. **Reusable Skill** — Repeatable process that any assistant can follow. No dedicated owner needed.
3. **Dedicated teammate** — Substantial, ongoing responsibility that deserves someone whose whole job is this.
4. **Dedicated teammate + Skill** — A dedicated owner plus a standardized workflow others can reuse.
5. **Dedicated teammate + Skill + Routine** — Stable recurring work that should run on a schedule or event, but only after the workflow has proven reliable.

## How to choose

- Rare, fuzzy, or one-off → 1
- Repeatable, but not a full job → 2
- Recurring, high volume or high stakes, needs an owner → 3
- Same as 3, and the steps should be written down as a playbook → 4
- Same as 4, and it should fire without being asked, *after* training has succeeded → 5

Default down, not up. A skill is usually better than a teammate. A teammate is better than a teammate plus a schedule. Never skip from pain to automation.

If they need a source that is not connected, name it and offer the connector as part of the prescription, not as a separate IT project.

## After the diagnosis

Confirm it with the user. If they agree and a dedicated teammate is the prescription, offer to create it and run Design AI Teammate. If the prescription is assistance or a skill only, build that and stop. Do not invent extra infrastructure.
