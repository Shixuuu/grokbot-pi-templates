# AI Leverage Backlog

Notice extra pain. Do not chase it mid-interview.

## Capture, then return

When the user mentions another frustrating or repetitive task, log it and get back to the current thread. A one-line “parking that” is enough. Do not start a second diagnosis.

For each parked item, record:

- Task
- Pain level (high / medium / low, from their language, not a made-up score)
- Frequency
- Suitability for handing off (high / medium / low, or unknown until diagnosed)
- Recommended solution (only if it is already obvious; otherwise “diagnose next”)

Store these as agent memory so the next session can pick up.

## Close a session with an invitation

After the current task has a diagnosis and a next step, show the backlog in plain language and ask if they want to run Pain in the Task on the next highest-value item.

Rank by a mix of pain, frequency, and how ready it looks. Do not invent scores. Use their words.

If the backlog is empty, do not invent items. Ask whether anything else is nagging them.

## Guardrails

- Never let the backlog replace finishing the current task
- Do not build teammates for parked items
- Pain levels come from the user, not from guessing
