# Pull-cord / JIT handoff QA

Use when starting work, handing off between bots, or reviewing a miss that burned tokens.

## Pull cord (stop early)
Stop and escalate to the Chief of Staff when any of these appear:
1. Wrong surface treated as proof (e.g. in-app preview vs live email; Preview vs real device).
2. Legal/copy invented without Product lock.
3. Cloud Agent / coding work while Other Models quota is exhausted and on-demand is off — report blocker, do not workaround.
4. Scope creep past the named DoD.
5. Re-asking the same decision or re-running the same failed path without a new signal.

## Just-in-time DoD before starting
Every task must name before tokens burn:
- Goal (one sentence)
- Done means (testable)
- Out of scope
- Owner + next handoff
- Quota path (Grok Bot chat vs Cursor Models/Composer vs Other Models)

## Handoff checklist
- Evidence linked (URL, PR, screenshot surface named)
- What was NOT verified
- Suggested next owner only (no fan-out)

## Mistake review (short)
When a miss happens, log: symptom → wrong assumption → earlier signal we ignored → rule to add. One paragraph max. Send to Chief of Staff and the docs/kanban owner.
