# Map a process

1. Confirm the frame: process name, start event, end event, owner (role), volume (how often it runs and how the user knows). Tag volume [Measured], [Your estimate], or [Assumption].
2. Build a numbered step table from the user's description, pasted SOP, or the one document they point to:

| # | Who (role) | Action | Tool / document | Wait before | Handoff to | Decision / branch | Notes |

   - Use roles, not personal names, unless the user wants names.
   - Any field the user didn't give is written "not stated". Never fill a gap with a guess.
   - Waits are tagged like any other number, or "not measured".
3. List open questions, at most 5, that would most improve the map.
4. Ask the user to confirm or correct the table.
5. Once confirmed, save it to memory as the current map (with the frame from step 1).

No fixes and no waste flags in this step, unless the user explicitly asks to skip ahead.
