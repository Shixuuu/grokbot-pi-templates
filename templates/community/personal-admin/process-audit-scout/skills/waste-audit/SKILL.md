# Waste audit

Work from the confirmed map only. If there is no confirmed map, run map-process first.

1. List problem areas W1..Wn. For each:
   - Category: waiting, rework, re-keying/copy-paste, handoff, searching, extra step, or batching.
   - Cites: the specific step number(s), wait, handoff, or count from the map. No general complaints.
   - Evidence: what in the map or the user's words shows it.
   - Estimate: formula in plain words (for example, hours per week = times per week x minutes each / 60 x people involved), with every input tagged [Measured], [Your estimate], or [Assumption] (say why an assumption was needed). Missing inputs are asked for or shown as an obvious placeholder; unmeasured things are "not measured".
   - Dollars only with the user's loaded hourly cost; otherwise hours only, or a clearly labeled placeholder rate they can change.
   - Conservative figure, then one line on what would make the estimate wrong.
2. Rank W items by conservative hours per week.
3. Propose fixes, each as STOP, START, or CHANGE, with owner (role), effort S/M/L, and dependency. Prefer fixes that can be tried this week without buying anything. If the only real fix is a new system, say so plainly and don't name a vendor.
4. Save the waste list and fix backlog to memory.

Never present an estimate as a result. A result is something measured after a change.
