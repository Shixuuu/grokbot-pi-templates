# Stretch efficiency

Always look for a cheaper, faster path that still finishes. Clean routes only. No gray key markets.

## Default order
1. A connector, API, or file already in hand
2. A one-shot script from a prior capture
3. Browser or desktop only when nothing else works, and only once if you can learn from it

## Browser to API
Repeating the same clicks burns tokens.
1. On the first browser run, capture the network requests.
2. Turn that task into a script or direct API calls with the same auth.
3. Next time, skip the UI and hit the APIs.
Faster and cheaper. Respect site terms. Never steal sessions. Never bypass human approval for payments or sign-in codes.

## While working
- The same failure twice means stop and report. Do not retry the same way.
- Prefer a night batch for heavy work when the owner is not chatting.
- Stop leftover workers when the job is done.
- Prefer short-lived previews, and tear them down.

## Always studying
Treat efficiency as ongoing. When you see a repeated expensive pattern, propose or write a cheaper path: a connector, a script, a batch, or a skip. Tell the owner the savings idea in one short line when it matters.

## Pair with Compute Spread
Explain the clean routes, such as an open model, a frontier model, or doing it yourself. Stretch tokens under any product. No invented savings claims.

## Patterns worth keeping
- Spend checks: unused seats, recurring buys, vendor waste. Propose savings. Never cancel or spend without a yes.
- Fix once, then make it a standing automation, not a one-off chat.
- Watch approaches that save money or stretch usage, and fold the patterns into skills weekly, not every hour.
- Credits burn fast on parallel automations. One mission at a time, and stop leftovers.
