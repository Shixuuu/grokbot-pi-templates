# Redux the system

REDUX. Keep the system small. Two names, one job, merge.

A small team that works beats a directory nobody opens. Skills, specialists, and group chats rot the same way.

Bots are seats. Skills are shared. A seat owns judgment, access, and the conversation. A skill is the recipe every seat can run. Do not spin a new seat for a recipe.

**Rules are not craft.** Do not grow a rulebook for ordinary competence. That is intelligence + looking at peers. Keep real constraints (access, who deploys, freezes). Kill checklist skills that only restate competence.

## When
- Before writing a new skill, spinning up a specialist, or opening a group chat.
- On a weekly self-improvement pass: recap the week, then Redux.
- After a craft miss: prefer learning the job over minting a rule.

## Bar for something new
Only add it if all of these are true:
1. The work will happen again.
2. Nothing existing already does that job (skill, specialist, or chat).
3. The work is actually different, not the same job with a new label.
4. It is a **constraint or mechanics recipe**, not “do ordinary craft well.”

If the work is the same, merge. Prefer a skill the existing team can run over a new specialist. Prefer one chat over a second one for the same job.

## One-page brief before you name a bot
Before creating a new specialist, skill, or standing routine, answer these seven (one page max). If any answer is fuzzy, do not create yet — pause or do the job once in chat instead.

1. **One job** — one sentence.
2. **Systems it may read** — connectors, files, apps.
3. **Actions that need the user’s yes** — send, spend, delete, post, sign.
4. **Never-do list** — hard forbidden.
5. **First no-side-effect test** — how you prove it once without outbound harm.
6. **Where output lands** — which chat / file; silence when nothing changed.
7. **Schedule** — cron window, or only-when-asked.

Draft never sends alone. Prefer silence when nothing changed.

## Proven job → Skill → Routine
Before creating or enabling a **standing routine**, walk this ladder (after the one-page brief):
1. **Real task** — do the job once in chat (or with corrections from the user).
2. **Skill** — if it will repeat, save the mechanics as a shared skill.
3. **Second test** — run the skill again on a fresh instance; fix what broke.
4. **Routine** — only then schedule it.

Do not automate an unproven workflow. A one-shot watch with a deadline can skip the ladder; a weekly/daily standing digest cannot.

Official public bot rosters (guides, templates) are **job-sentence sources only**. Steal into existing specialists; never clone seats.

## The job explains the specialist
If you cannot say the job in one sentence the way you would hand it to a person, it is not a specialist yet. Watch jobs are Routines, not new bots.

## Hire by bottleneck, not by app
Do not create a Gmail bot, Chrome bot, or Notion bot because an icon exists.

## Contract, not personality
A new specialist ships with five fields: Job, Sources, Judgment, Output, Forbidden.

## Hard mode on skills
Treat skill-writing as expensive. A summary in chat is not learning. After a miss, run Learn from mistakes. After a repeated GUI flow, run Capture then script. One job, one skill. Do not add a skill that is just a checklist for competence.

## Overlap audit
List skills, specialists, and group chats. Merge, rewrite boundary, or drop. Weekly pass retires dead weight.

## Do not
- Add a skill that restates another with nicer words
- Add a specialist for work an existing one owns
- Clone someone else's org catalog
- Mint a team rule every time someone half-ships craft
- Create a standing routine that skips Proven job → Skill → Routine
- Mint ops, per-account, or prospecting fleets from public guides
