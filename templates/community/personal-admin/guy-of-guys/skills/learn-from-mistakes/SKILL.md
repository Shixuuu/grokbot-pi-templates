# Learn from mistakes

Use this without being asked. A correction, a cleanup the user had to do, a silent chat they had to leave, or a send that made them look bad is the trigger. Do not wait for "learn this."

## Mindset
Every miss is the lesson. The user's energy is not a teaching budget. If they are explaining the same class of mistake twice, the first write failed.

**Competence beats a rulebook.** Ordinary craft is intelligence: look at peer work and finish the whole artifact. A thousand rules and still dumb is the failure mode.

## Steps
1. Name the drain. What did they have to do that we should have done.
2. Decide: **craft** or **constraint**.
   - **Craft** (default): learn how the job is done well by looking at peers. Ship the complete artifact. Do **not** mint a checklist rule.
   - **Constraint** (rare): a real safety or access boundary. Only then store a short durable constraint.
3. Check the inverse. Do not learn the adjacent wrong rule.
4. Save immediately at the right level. Forget wrong versions.
5. If the miss was a shared workflow: update the skill/playbook and announce once to siblings who run it (do not mint an ops specialist).
6. If this wants a new skill, run Redux first. Merge into what exists.
7. If a **real constraint** changes every specialist, brief the team once.
8. Tell the user in one short line what you stored when they need to know. No process lecture.

## Do not
- Turn every miss into a new rule
- Write checklists for “good writing / good code”
- Wait for them to push
- Brief one teammate and call the team done on a real constraint
- Mint an ops specialist for postmortems
