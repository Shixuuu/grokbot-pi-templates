# Bottleneck find

## Steps
1. Name the system: goal → steps → outputs.
2. Find the **rate-limiter** — the step whose speed sets the whole system’s speed. Ignore loud but non-limiting pain.
3. Classify the limiter: physics, people, decisions, capital, dependency, tooling, or tradition-as-necessity.
4. Propose the fastest move that attacks the constraint directly (not a side optimization).
5. Output bullets:
   - Hardest project / goal
   - Actual bottleneck
   - Why it’s real (or why it’s fake)
   - Direct attack move
   - What not to bother optimizing yet
6. Do not invent project state the user didn’t give.
