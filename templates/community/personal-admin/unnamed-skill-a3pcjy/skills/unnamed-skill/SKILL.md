# 微信 / 支付宝账单进口

把支付账单变成可核对的个人账本。优先吃 **支付宝 / 微信支付导出的 CSV（或 Excel）** 和 **账单页截图**；不要引导用户登录银行 App，也不要索要支付密码、短信验证码、支付 cookie。

## 首次上手（只做一次）

1. 问清账本落点（三选一即可）：Google Sheet / 本地 CSV 或 Markdown 表 / Notion 数据库。没有现成表就按选定工具新建，表头至少含：`日期 | 时间 | 金额 | 收支 | 账户 | 商户 | 分类 | 备注 | 来源文件 | 指纹`。
2. 约定默认币种为 `CNY`；若账单自带外币，保留原币并另记折算备注（不瞎编汇率）。
3. 给出默认可改的中文分类：餐饮、交通、日用、住房、通讯、娱乐、医疗、教育、人情、购物、订阅、工资、转账、红包、其他收入、其他支出。
4. 用 3–5 行说明用户怎么导出账单：
   - 支付宝：账单 → 导出 → 邮箱/下载 CSV
   - 微信：微信支付 → 账单 → 导出（按当前官方路径；若界面变了，让用户贴一张设置页截图再指路）
5. 明确安全边界：只处理用户主动丢进来的文件/截图；永不代登支付 App；永不保存密钥。

## 每轮进口

1. 识别来源：`alipay` / `wechat` / `mixed` / `unknown`。不明就先问一句，不要猜错账户。
2. 解析字段：日期时间、金额、收支方向、对方/商户、商品说明、收/支账户、交易状态（只入「交易成功」；关闭/失败跳过并计数）。
3. 生成指纹：`账户|日期|金额|商户|说明` 归一化后哈希或拼接；与账本已有指纹比对，**重复的默认跳过**，在摘要里报「新增 / 跳过重复 / 解析失败」。
4. 自动分类：先规则（商户关键词、说明关键词），再对拿不准的标 `待确认`；不要把转账、红包、信用卡还款误记成消费，除非用户规则如此。
5. **写入前先给预览表**（最多展示 20 行样例 + 全量统计）：新增笔数、支出合计、收入合计、Top 分类、待确认条数。等用户明确说「写入 / 确认」再落账。
6. 写入后回传：落账笔数、跳过重复、失败行（附原因）、账本链接或文件路径。

## 截图模式

- 一张图可含多行；看不清的金额/商户标 `待确认`，宁可少记不错记。
- 多张图按时间排序合并；同一屏幕重复截的按指纹去重。
- OCR 不确定时把原图引用留给用户，不编造数字。

## 日常对话（进口之外）

- 「本月花了多少 / 某分类 / 某商户」：只基于已入账数据回答，并注明统计区间。
- 「改分类规则」：记住用户纠正，后续同类商户沿用。
- 「撤销上一批」：按 `来源文件` 或导入批次撤，先预览再删。

## 不要做的事

- 不自动开通银行连接、不爬邮箱里的一切附件（除非用户指定某封导出邮件）。
- 不在未确认时批量改历史分类。
- 不把模板使用者的真实姓名、账号、具体余额写进可分享配置。
