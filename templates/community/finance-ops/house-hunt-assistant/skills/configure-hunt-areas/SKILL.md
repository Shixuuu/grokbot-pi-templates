# Configure hunt search

Use on first import, whenever the buyer changes **where** / **what** to search, or when results are quiet / not what they want.

## First run — onboarding (keep tiny)
Welcome in one warm line, then ask **only**:
1. Where to search (cities / neighborhoods / zips)
2. Max price

Save starter defaults (below). Confirm with a short “you’re set” recap and optional next lines:
- “change filters”
- “show me homes tonight”
- “how much house can I afford”

**Do not** interview must-haves, beds, or commute on first run unless they volunteer.

## Starter defaults
| Filter | Default |
|--------|---------|
| Status | Active + Coming Soon |
| Home type | Detached single-family |
| Max price | What they just said |
| Min price / beds / baths / sqft / year | Any |
| Must-haves | None |
| Soft skip | Obvious teardowns / as-is shells |
| Townhomes | Off |

## Quiet market / “not seeing what I want” (light re-onboarding)
When a watch finds nothing new for a while, or the buyer says results are wrong/thin/not their vibe:
1. One short empathy line + what the current filters are.
2. Offer **one** easy tweak menu (not a full restart), e.g.:
   - Widen or add nearby areas
   - Raise max price a notch
   - Relax a must-have
   - Allow townhomes / different home type
   - Drop a soft-skip that’s too strict
3. Apply only what they pick; confirm the new filter set.
4. Optionally run a one-time fresh scan after the tweak.

Don’t nag every quiet watch — at most a light nudge after repeated empty runs or when they complain. Never reset their whole setup without asking.

## Later tweaks (when they ask)
Update only the fields they name. Don’t restart onboarding.

## Save
Durable memory: geography, max price, filter set. Update house-hunt-watch if it still hardcodes old areas/filters.

## Confirm
“Searching [areas] under [max]. Defaults on — say change filters anytime.” No full scan unless asked.
