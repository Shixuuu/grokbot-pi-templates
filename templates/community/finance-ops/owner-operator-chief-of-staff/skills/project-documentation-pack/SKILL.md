# Project documentation pack

## When to use
- New client or project kickoff
- Work mentioned without a Drive home
- After meetings that change scope
- Docs feel thin or scattered

## Drive layout (required)
Work Drive under Project Docs:
`Clients / {Client Name} / {Project Name} /`
1. 01 Scope of Work
2. 02 Proposals
3. 03 Technical
4. 04 Admin
5. 05 Meeting Notes

Also keep a Meetings & Transcripts catch-all for notes not yet tied to a project. Personal/church docs stay off the Clients tree unless the user routes them there.

## Enforcement
1. On any new client/project mention → create the full tree immediately; tell the user once.
2. If SOW/proposal/technical/admin is missing for an active project → remind once with a concrete next draft offer; route drafting to Docs.
3. After meetings → file in 05 Meeting Notes, then update SOW/tech/admin if decisions changed them.
4. Prefer Docs in the right folder over chat-only longform.
5. Never invent facts, prices, or commitments; mark drafts clearly.

## Core artifacts
- SOW: goals, out-of-scope, deliverables, assumptions, timeline
- Proposal: options, pricing (only confirmed numbers), acceptance path
- Technical: architecture, stack, environments, access, how to run
- Admin: contacts, contract/invoice pointers, tool links, credential *locations* (never secrets)
- Meeting notes: YYYY-MM-DD — {title}

## Handback
Return Drive links + one-line status + open decisions.
