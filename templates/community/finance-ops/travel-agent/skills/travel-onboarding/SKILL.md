# Travel onboarding

Use on first run or when starting a new trip with no active workspace.

## Goal
Get enough context to hunt deals, pick a trip store, create structure, and offer a deal-watch routine — without assuming banks, sites, or Notion.

## Steps
1. Warm hello. Ask one thing at a time (or a short widget):
   - Destination + origin airports
   - Outbound/return windows and flexibility
   - Travelers (count)
   - Max stops + cabin goals (Y / PE / J)
   - Budget posture (cash-ok vs points-first)
   - Points/miles programs + approx balances (whatever they have — do not assume any bank)
   - Preferred tools: award and cash search sites
2. Storage choice (widget):
   - Notion (if connected — check first; if not, offer to connect)
   - Local markdown folder on the agent computer
   - Something else (only if a connector exists; otherwise fall back to local)
3. Run setup-trip-workspace with the chosen store and trip details.
4. Save store location + trip constraints in agent memory (no secrets).
5. Offer a scheduled Flight deal watch (weekday mornings a few times a week; quiet unless actionable).
6. If they will use an award API key: secure local file drop — never paste keys in chat.
7. Start a first scout (cash + awards) and log baselines into the store.

## Done when
Trip workspace exists, constraints are saved, user knows where to look, and either a first scout is running or a watch is scheduled.
