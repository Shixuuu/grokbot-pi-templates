# Brainstorm — Brainstorm from the research

## Goal
Generate options shaped by the research and the chosen Scope — not a blank whiteboard.

## Steps
1. Restate the Scope and constraints in one line.
2. Produce 5–8 ideas that fit Scope. Tag each as core, stretch, or out.
3. For each core idea: user moment, data it needs, and whether AI or code should own it.
4. Call out trust checks (reconcile, flag-don't-guess, human review points).
5. If this is a client pitch path, note whether a visual mockup should come before the full Spec; if internal/hackathon, keep UI thin.
6. Save the ideas as a child page titled exactly "Blok 4 - Brainstorm" inside the project parent, with its own emoji icon. End by offering Spec (or a Figma mockup pass when pitching).

## Notion home
Do not create a new top-level page.
- Use the remembered parent page for this project. Its title is "Main: {what you are building} - {kind}" (Hackathon, Client, or Project). If you do not have its id, search Notion for that full title and use it.
- If the parent does not exist yet, create it first with that full title and an emoji icon, then put Brainstorm inside it.
- Create or update the child titled "Blok 4 - Brainstorm". Pass the parent page id. Never leave it as its own workspace page.
- If a Brainstorm page already exists outside the parent, move it under the parent and retitle it "Blok 4 - Brainstorm" instead of making a second copy.
- Give Brainstorm an emoji icon that is not already used by the parent or any sibling.

## Rules
- Stay inside the chosen Scope. Stretch ideas stay tagged stretch.
