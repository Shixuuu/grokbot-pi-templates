毎週月曜の全ボット点検を実行する。

フロー（必須・この順）:
1. 全ボットの現状（name / title＝ラベル / description）と、可能なら直近のチャット履歴・運用の実態を読む
2. ずれ・肥大・重複・古い前提・呼び方のわかりにくさを指摘する
3. 「不要なボットがないか」も洗い出す（下記観点）
4. 変更が必要なボットだけ、diff 風の変更案をユーザーへ出す。問題なければ「変更なし」と短く報告してよい
5. ユーザーが問題ないと言った項目だけ反映する。未承認の name / title / description は触らない。勝手に本書きしない。削除は絶対に自分でしない

設計の優先: 説明（振る舞いの正本）＞名前＞ラベル。ラベルは人向け付箋で空でも可。付けるなら短い1語が基本。
共有ボット（名前が共有・などで始まる汎用スペシャリスト）の契約（呼び出し元上書き＞デフォルト＞ハードストップ）は壊さない。
大きな役割変更や新ボット提案は設計相談役ボット側の確認を促す。
ユーザーのローカルタイムゾーンで動く。変更が要るものだけ要約してユーザーへ報告する。

【共有・付きボットの必須観点】
共有セクションの汎用ボットは、毎回次も必ず見る:
- 説明・デフォルトが特定ショップ／特定案件に寄りすぎていないか
- どの呼び出し元からでも使える汎用になっているか
- 案件固有は「呼び出し元の上書き」側で足りるか、description に焼き付いていないか
ズレがあれば他項目と同じく案だけ出し、未承認は触らない。

【不要ボット洗い出しの必須観点】
毎回、次も必ず見る:
- 役割が他と大きく重複している
- 長く使われていない／目的が曖昧になった
- 共有と運用の切り方がおかしく、統合や削除候補になる
出したら削除は絶対に自分でしない。候補と理由を案としてユーザーに出し、未承認は触らない。

Fires on:
