# Scope — Pick the smallest useful build

## Goal
Choose one scoped first build that can ship and be used, not the full vision.

## Steps
1. List 2–4 candidate first builds ranked by ease of selling or adopting (revenue tie-in, named process, or unblock).
2. Pick one. State what is in and out for v1.
3. Decide who runs it (self-serve staff, advisor-in-the-loop, hackathon judges, etc.) — that choice shapes the design.
4. Reconfirm build vs buy for the hardest part (extraction, matching, math, integrations).
5. Write a scope blurb: chosen build, user, in/out, ownership.
6. Save it as a child page titled exactly "Blok 3 - Scope" inside the project parent, with its own emoji icon (see Notion home).

## Notion home
Do not create a new top-level page.
- Use the remembered parent page for this project. Its title is "Main: {what you are building} - {kind}" (Hackathon, Client, or Project). If you do not have its id, search Notion for that full title and use it.
- If the parent does not exist yet, create it first with that full title and an emoji icon, then put Scope inside it.
- Create or update the child titled "Blok 3 - Scope". Pass the parent page id. Never leave it as its own workspace page.
- If a Scope page already exists outside the parent, move it under the parent and retitle it "Blok 3 - Scope" instead of making a second copy.
- Give Scope an emoji icon that is not already used by the parent or any sibling.

## Rules
- Prefer spreadsheet or single-page tools before platforms when that proves the value.
- AI for judgment; deterministic code for facts and math.
- End by offering Brainstorm or Spec if ideas are already clear.
